# Security — ArbitrPack

Полная модель угроз: [`docs/threat-model.md`](docs/threat-model.md). Здесь — краткая сводка мер и правила
раскрытия уязвимостей.

## Реализованные меры (см. threat-model.md для деталей и ссылок на код/тесты)

- Allowlist форматов файлов (PDF/JPG/JPEG/PNG), проверка MIME по содержимому (`python-magic`), не только по расширению.
- Защита от path traversal и двойных расширений в именах файлов.
- Лимиты размера файла (30 МБ) и батча (300 МБ / 50 файлов), настраиваемые в `packages/validation-rules/rules.yaml`.
- Защита от zip-slip и zip-bomb при сборке итогового архива.
- Rate limiting на upload (`30/hour` на IP) и webhook (`120/minute`).
- Secure HTTP-заголовки (X-Content-Type-Options, X-Frame-Options, Referrer-Policy, HSTS в production).
- HttpOnly + SameSite=Lax + Secure (prod) cookies для сессии.
- Платежи: webhook никогда не доверяется напрямую — статус всегда перепроверяется через API провайдера; идемпотентность
  обработки событий; сверка суммы/валюты.
- Временные подписанные токены скачивания (TTL 15 минут по умолчанию), хранится только их SHA-256 хэш.
- TTL-удаление файлов, пользовательская команда немедленного удаления, отдельный аудит удаления.
- Удаление EXIF из изображений и метаданных PDF как часть платной обработки.
- Структурированные логи без содержимого документов и без оригинальных имён файлов (проверено тестами).
- Секреты только через переменные окружения, не хранятся в git (`.gitignore`, `.env.example` без реальных значений).

## Известные ограничения MVP (не реализовано, осознанно)

- **Антивирусное сканирование (ClamAV)** — интерфейс подготовлен, но демон ClamAV не подключён в `docker-compose.yml`
  в этой версии. Для запуска с публичным трафиком рекомендуется подключить `clamd` перед `storage.put()` в
  `app/routers/upload.py` — см. `docs/threat-model.md`.
- **CSRF-токены** — не реализованы отдельно; риск оценён как низкий при текущем наборе операций (см. threat-model.md).
- Реальная интеграция ЮKassa не протестирована против боевого API (только против замоканных HTTP-ответов) — ключи
  тестового магазина не были предоставлены владельцем в рамках этой сессии.

## Раскрытие уязвимостей

Домен `baikalproject.pro` зарегистрирован, но контактный адрес (например, `security@baikalproject.pro`) пока не
подтверждён владельцем как реально работающий почтовый ящик — здесь не публикуется адрес, который может оказаться
несуществующим. **OWNER ACTION REQUIRED:** завести почтовый ящик на домене (или указать любой другой реально
рабочий контакт) и вписать его сюда перед реальным запуском.
