# Маркетинговый пакет: запуск через Яндекс Поиск

Точка установки аппарата — поисковый спрос. Частотность и стоимость клика НЕ выдуманы: доступа к Яндекс.Вордстат
и рекламному кабинету в рамках этой сессии не было, поэтому соответствующие поля помечены `UNKNOWN`. Владельцу
нужно подставить реальные значения перед запуском (таблица в конце файла).

## Карта поисковых намерений

| Намерение | Пример запроса | Коммерческий сигнал | Частотность (Вордстат) | Комментарий |
|---|---|---|---|---|
| Ошибка при подаче | "мой арбитр ошибка загрузки файла" | высокий | `UNKNOWN` | Прямое совпадение с болью продукта |
| Ошибка формата | "мой арбитр не принимает pdf" | высокий | `UNKNOWN` | — |
| Требования к файлам | "требования к электронным документам арбитражный суд" | средний | `UNKNOWN` | Информационный, но близкий к конверсии |
| Как подать документы | "как подать иск через мой арбитр" | средний | `UNKNOWN` | Часть аудитории впервые сталкивается с системой |
| Проблема с подписью | "мой арбитр усиленная квалифицированная подпись ошибка" | средний | `UNKNOWN` | Не наша зона (см. R-6) — в объявлении не обещаем решение подписи |

## Минус-слова (для исключения нецелевого трафика)

`бесплатно скачать`, `образец искового заявления`, `юрист бесплатно`, `консультация юриста онлайн бесплатно`,
`вакансии`, `работа`, `суд онлайн смотреть`, `решение суда скачать`, `арбитражный суд адрес`, `арбитражный суд телефон`,
`арбитражный управляющий` (омонимия с "мой арбитр", другая тематика), `курсы`, `обучение`.

## 3 варианта заголовка

1. «Мой Арбитр» не принимает файлы? Проверим за 2 минуты
2. Ошибка при подаче документов в суд — найдём причину
3. Технические требования к файлам для «Мой Арбитр» — проверка онлайн

## 5 вариантов объявлений (заголовок + текст, в рамках типовых ограничений Яндекс.Директ)

1. **Заголовок:** Ошибка загрузки в «Мой Арбитр»?
   **Текст:** Проверим PDF и сканы за 2 минуты: формат, размер, повреждения. Бесплатная диагностика, оплата только за готовый архив. Не юридическая консультация.

2. **Заголовок:** Файл не проходит в «Мой Арбитр»
   **Текст:** Найдём техническую причину: шифрование, повреждённый PDF, превышение размера. Исправим что можно автоматически.

3. **Заголовок:** Проверка документов перед подачей в суд
   **Текст:** Технические ошибки в файлах — частая причина отказа загрузки. Диагностика бесплатна, готовый архив — по фиксированной цене.

4. **Заголовок:** Требования к файлам для арбитражного суда
   **Текст:** PDF, JPG, PNG — проверим формат и размер по действующим техническим требованиям. Результат за минуты.

5. **Заголовок:** Срочно нужно подать документы в суд?
   **Текст:** Проверим комплект файлов технически, соберём аккуратный архив. Без юридических гарантий приёма судом — только техническая подготовка.

## 3 ценностных предложения

1. **Скорость**: результат диагностики за минуты, без очередей и звонков в поддержку суда.
2. **Прозрачность**: список всех найденных проблем показывается бесплатно, до оплаты.
3. **Честность**: сервис прямо говорит, чего не может — не подписывает документы и не гарантирует принятие судом.

## Структура UTM

```
utm_source=yandex
utm_medium=cpc
utm_campaign={ad_group_theme}   # напр. error-upload, requirements, urgent
utm_content={ad_variant_id}     # напр. ad1..ad5
utm_term={keyword}              # автоподстановка Яндекс.Директ, если включена
```

Пример: `https://baikalproject.pro/?utm_source=yandex&utm_medium=cpc&utm_campaign=urgent&utm_content=ad5`

Frontend уже читает `utm_source`/`utm_medium`/`utm_campaign` из query-параметров при первом обращении к `/api/upload`
(создание `UserSession`, см. `app/routers/upload.py::get_or_create_session`) — значения сохраняются в БД для
последующей атрибуции конверсий без сторонних трекеров.

## События конверсии (для целей в Яндекс.Директ/Метрике, если будет подключена)

1. `upload_completed` — файлы загружены (микро-конверсия).
2. `diagnostics_free_result_shown` — увидел бесплатный результат (микро-конверсия).
3. `checkout_started` — начал оплату (макро-конверсия, ценность = потенциальная выручка).
4. `payment_succeeded` — оплатил (макро-конверсия, ценность = `amount`).

Все эти события уже пишутся в `analytics_events` — при подключении Метрики достаточно продублировать вызов
`ym(COUNTER_ID, 'reachGoal', 'payment_succeeded')` рядом с существующим кодом на фронтенде (см. `app/result/[batchId]/page.tsx`), не передавая при этом ни имён файлов, ни `batch_id` в публичный трекер.

## Минимальный сценарий A/B-теста

- **Гипотеза**: заголовок с явным указанием "бесплатная диагностика" даёт более высокий CTR, чем заголовок без цены.
- **Вариант A**: объявление №1 (без слова "бесплатно" в заголовке).
- **Вариант B**: объявление, где в заголовке явно "Бесплатная проверка файлов за 2 минуты".
- **Метрика решения**: CTR за первые 200–500 показов на группу, затем конверсия `checkout_started` за первые 20 переходов на группу.
- **Длительность**: до достижения ~100 кликов на вариант или 7 дней, что раньше.
- **Инструмент**: сплит на уровне групп объявлений в Яндекс.Директ (не требует стороннего ПО).

## Правила остановки неэффективной рекламы

Остановить группу объявлений/кампанию, если выполняется любое из условий:

1. Потрачено ≥ 3 × ожидаемая цена одной оплаты (399 ₽ × 3 = 1197 ₽) без единой оплаты — *после* первых 50 кликов.
2. CTR группы < 0.5% после 1000 показов (сигнал нерелевантного объявления/аудитории).
3. Конверсия `upload_completed → payment_succeeded` < 1% после 30 полных бесплатных диагностик — сигнал проблемы в
   продукте/цене, а не в объявлении (тогда правильное действие — не масштабировать рекламу, а разобраться в продукте).
4. Допустимый CAC (см. `docs/economics.md`) превышен за скользящее окно 3 дня.

## Обязательное условие перед реальным запуском рекламы (раздел 12 ТЗ)

Реклама включается ТОЛЬКО после того, как владелец лично прошёл полный сценарий на реальном (не dev) окружении:
загрузка → диагностика → тестовая оплата → обработка → скачивание → удаление. Это `OWNER ACTION REQUIRED` — сессия
не может выполнить это действие за владельца, так как требует доступа к продакшен-домену и решения о запуске трат.
