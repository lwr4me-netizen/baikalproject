# Продуктовая аналитика ArbitrPack

Первого лица, без сторонних трекеров. Хранится в таблице `analytics_events` (см. `app/models.py`).
Никогда не содержит имён файлов, содержимого документов или значений полей форм, кроме перечисленных ниже.

## События (реализованы в `app/services/analytics.py::VALID_EVENTS`)

| Событие | Когда фиксируется | Свойства |
|---|---|---|
| `upload_started` | Пользователь отправил файлы на `/api/upload` | — |
| `upload_completed` | Файлы успешно сохранены и продиагностированы | `file_count` |
| `diagnostics_free_result_shown` | Бесплатный отчёт показан | сводка (`critical_count`, `warning_count`, ...) |
| `checkout_started` | Создан платёж | `amount` |
| `payment_succeeded` | Webhook подтвердил успешную оплату | `amount` |
| `payment_failed` | Webhook сообщил об отмене/ошибке | `status` |
| `archive_created` | Платный ZIP собран | — |
| `archive_downloaded` | Файл скачан по токену | — |
| `data_deleted` | Данные удалены (по TTL или вручную) | `reason` |

Не реализованы отдельными событиями в MVP (не являются блокером для запуска, техническая заметка): `page_view` на уровне
статических страниц лендинга (частично покрывается через создание `UserSession` при первом обращении к API), `return_visit` (можно вывести из `last_seen_at` в `UserSession`, отдельного события не заведено).

## Метрики защищённого отчёта `GET /api/admin/metrics`

Доступ по `Authorization: Bearer <ARBITRPACK_ADMIN_TOKEN>`.

- `visitors` — количество созданных `UserSession`.
- `checks_started` / `checks_completed_free` — по числу уникальных `batch_id` с соответствующими событиями.
- `payments_succeeded`, `conversion_to_payment`, `average_check_rub`, `revenue_rub`.
- `top_issue_categories` — самые частые категории проблем (`ValidationResult.rule_code`), топ-10.

## Метрики, требующие внешних данных (не считаются автоматически)

- **Стоимость привлечения (CAC)** — требует данных рекламного кабинета Яндекса (расход по кампаниям). См. `docs/economics.md` — поле `UNKNOWN` до подстановки владельцем.
- **Прибыль до/после рекламных расходов** — производная от CAC и `revenue_rub`, считается в `docs/economics.md`.
- **Возвраты (refunds)** — в MVP модель `PaymentStatus.refunded` заведена в схеме БД, но эндпоинт инициации возврата через API ЮKassa не реализован (см. финальный отчёт, `OWNER ACTION REQUIRED` при необходимости).

## Явный отказ от сторонней аналитики

По требованию раздела 11 ТЗ, сервис не подключает Google Analytics/Яндекс.Метрику/Facebook Pixel и подобные инструменты
в том виде, где им передаются URL с содержимым или именами файлов. Если владелец решит подключить Яндекс.Метрику для
маркетинговой аналитики (счётчик визитов/конверсий), необходимо: (1) не передавать в неё `batch_id`, имена файлов
или содержимое `ValidationResult`; (2) настроить цели по разделу `docs/marketing-yandex.md` (только клики по кнопкам
и переходы между экранами, без ПДн).
