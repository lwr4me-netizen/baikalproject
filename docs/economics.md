# Экономическая модель ArbitrPack

Все параметры конфигурируемы (см. `packages/validation-rules/rules.yaml` → `pricing`, и таблицу ниже для параметров,
которые не хранятся в коде). Ничего из цифр CAC/CTR/конверсии рекламы не выдумано — при отсутствии реальных данных
Яндекс.Вордстат/рекламного кабинета поле помечено `UNKNOWN`.

## Вход: таблица параметров (заполняется владельцем перед расчётом реальных сценариев)

|---|---|---|---|
| Цена одной обработки | 399 ₽ (`rules.yaml: pricing.full_processing_price = 39900` копеек) | продуктовое решение, легко меняется | КОНФИГУРИРУЕМО |
| Комиссия платёжного провайдера (ЮKassa) | `UNKNOWN` — зависит от тарифа, выбранного при регистрации магазина (обычно в диапазоне, публикуемом на yookassa.ru/pricing на момент подключения) | официальный тариф ЮKassa | UNKNOWN — владелец должен проверить актуальный тариф своего магазина |
| Стоимость хранения (S3/MinIO + VPS) | `UNKNOWN` — зависит от выбранного VPS-тарифа и объёма | тариф хостинг-провайдера | UNKNOWN |

| Ставка возвратов | `UNKNOWN` (принять 0% на старте, скорректировать по факту) | — | UNKNOWN — предположение, не измерение |
| Налоговый режим | `UNKNOWN` — зависит от организационно-правовой формы владельца (ИП на УСН, самозанятость и т.д.) | требует решения владельца | OWNER ACTION REQUIRED |

## Формулы

```
Валовая прибыль с одной оплаты = Цена − Комиссия_провайдера − Переменная_стоимость_обработки(хранение+вычисления на 1 заказ)
Чистая прибыль с одной оплаты = Валовая прибыль − CAC_на_одну_оплату − Налог
Точка безубыточности (заказов/мес) = Постоянные_расходы_в_месяц(VPS+домен) / Валовая_прибыль_с_одной_оплаты
Допустимый CAC = Валовая_прибыль_с_одной_оплаты × (1 − целевая_норма_чистой_прибыли)
```

## Сценарии

Каждый сценарий требует подстановки реальных значений комиссии/CAC/расходов. Ниже — структура расчёта с плейсхолдерами;
реальные числа появятся только после того, как владелец внесёт данные в таблицу выше. **Никакие цифры выручки/прибыли
ниже не являются прогнозом** — это шаблон, который считает сам себя, если параметры известны.

### Пессимистичный

- Конверсия бесплатная диагностика → оплата: `UNKNOWN` (предположение для расчёта чувствительности: 2%)
- CAC: `UNKNOWN`
- Возвраты: `UNKNOWN` (предположение: 5%)
- **Результат: не может быть рассчитан без реальных данных Яндекс.Директ и тарифа ЮKassa.**

### Базовый

- Конверсия: `UNKNOWN` (предположение для расчёта чувствительности: 5%)
- CAC: `UNKNOWN`
- Возвраты: `UNKNOWN` (предположение: 2%)
- **Результат: не может быть рассчитан без реальных данных.**

### Оптимистичный

- Конверсия: `UNKNOWN` (предположение для расчёта чувствительности: 10%)
- CAC: `UNKNOWN`
- Возвраты: `UNKNOWN` (предположение: 1%)
- **Результат: не может быть рассчитан без реальных данных.**

## Как посчитать реальные сценарии (инструкция владельцу)

1. Получить актуальный тариф ЮKassa для своего магазина (личный кабинет ЮKassa → Тарифы).
2. Выбрать VPS-тариф и посчитать месячную стоимость (постоянные расходы).
3. Запустить тестовую рекламную кампанию в Яндекс.Директ на небольшой бюджет, дождаться данных по CPC/CTR/конверсии
   из отчёта `/api/admin/metrics` (поле `conversion_to_payment`) — это и есть реальная конверсия для расчёта.
4. Подставить значения в таблицу выше и пересчитать формулы (можно прямо в этом файле или в отдельной таблице).
5. Точка безубыточности и допустимый CAC становятся конкретными числами только после шага 3–4.

Автоматизация: `GET /api/admin/metrics` уже считает `revenue_rub`, `payments_succeeded`, `average_check_rub`,
`conversion_to_payment` на основе реальных платежей ArbitrPack — этого достаточно для заполнения "выручка" и
"конверсия" без догадок, как только появятся первые платежи.
